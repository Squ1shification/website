WinFsp — Kernel Out-of-Bounds Read & Pool Memory Disclosure

WinFsp kernel driver CWE-125 CVSS 7.1 Credited — v2.2B4

The kernel worker FspVolumeNotifyWork checks the lower bound of each FSP_FSCTL_NOTIFY_INFO record’s 16-bit Size field but never the upper bound against the remaining input buffer. A single record with Size = 0xFFFF in a ~10-byte buffer makes the driver treat adjacent non-paged pool as a ~65 KB wide-character path and walk ~64 KB past the allocation. The device \Device\WinFsp.Disk grants read access to Everyone, so any unprivileged local user can reach it.

Impact is twofold: a deterministic PAGE_FAULT_IN_NONPAGED_AREA bugcheck (DoS), and — because the walked bytes are handed back to user mode through directory change-notifications — disclosure of kernel non-paged pool memory (150/150 successful leaks in testing), enough to defeat KASLR. Resolved by one bounds check validating Size against the remaining buffer.

if (NotifyInfo->Size > (ULONG_PTR)NotifyInfoEnd - (ULONG_PTR)NotifyInfo) break; // missing upper-bound check
Release credit (v2.2B4)

OpenSMTPD (OpenBSD) — Raw-Modifier Bypass to Code Execution

OpenSMTPD / mda_unpriv.c Env-var / command injection OpenBSD 7.9 errata 015 CVE pending

When OpenSMTPD expands address variables with the raw modifier, the user- and domain-derived components were written into the mail-delivery agent’s environment without filtering. Crafted addresses could smuggle the very characters the raw modifier is meant to strip, reaching command execution in the MDA context. Reported to the OpenSMTPD maintainer and fixed in OpenBSD 7.9: mda_unpriv.c rev 1.10 adds mda_escape(), which filters MAILADDR_RAW_ESCAPE characters across all six address fields before the environment is built. CVE assignment is pending.

Sliver C2 — Unauthenticated PNG-Decoder Memory-Exhaustion DoS

BishopFox Sliver HTTP(S) listener DoS / resource exhaustion CVE-2026-77622

Two issues in Sliver’s HTTP(S) implant-traffic PNG path. The encoder draws from only 65,537 possible nonces, making the channel brute-forceable; and the listener decodes attacker-supplied PNGs with no size or dimension limit. An unauthenticated attacker brute-forces the nonce, then sends a small “PNG boomer” (e.g. 32767×32767) that decompresses to gigabytes, exhausting RAM and crashing the C2 server. Affects Sliver 1.7.3.

Nextcloud — SubAdmin → DelegatedAdmin Privilege Escalation

Nextcloud server Broken access control Resolved

Nextcloud’s SubAdmin::isUserAccessible() decides whether a group admin may manage another user. It correctly blocked SubAdmins from touching full admin accounts but never checked the DelegatedAdmin role. A SubAdmin sharing any single group with a DelegatedAdmin could reset that account’s password or email through the OCS Provisioning API and inherit its instance-wide user-management rights — a jump from group-scoped admin to global user manager, and full takeover of the DelegatedAdmin account. Fixed by also rejecting DelegatedAdmin targets in the access-control check.

Google OSS VRP — Carbon-lang Pre-Commit Artifact Poisoning

carbon-language/carbon-lang CI/CD · artifact poisoning Accepted

A pull_request workflow ran a fork’s pre-commit hooks and uploaded the resulting git diff plus the GitHub event file as an artifact. A privileged workflow_run job then fed that attacker-controlled diff to reviewdog using a bot PAT — with no same-repository/fork check. A malicious fork PR could therefore post arbitrary review comments as the trusted bot account, and by rewriting the copied event file, retarget reviewdog at any PR number. harden-runner in block mode stopped exfiltration, but api.github.com stayed reachable. A textbook artifact-poisoning chain: untrusted fork output consumed by a secrets-bearing workflow.
