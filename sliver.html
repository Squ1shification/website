Sliver C2: Unauthenticated PNG-Decoder Memory-Exhaustion DoS

BishopFox Sliver · HTTP(S) listener · DoS / resource exhaustion · CVE-2026-77622 · affects 1.7.3

An unauthenticated attacker can crash a Sliver C2 server by sending a tiny PNG that decompresses to gigabytes.

Two problems
  • Small nonce space. Sliver’s image-based C2 channel draws from only 65,537 possible nonces, so the value guarding the path can be brute-forced.
  • Unbounded decode. The HTTP(S) listener decodes attacker-supplied PNGs with no cap on file size or declared dimensions.
The attack

Brute-force the nonce to reach the PNG-processing path unauthenticated, then send a “PNG boomer”: a small, highly-compressed file that declares enormous dimensions (for example 32767×32767). Decoding allocates the full raster, gigabytes of memory, exhausting RAM and crashing the host running the Sliver server. No authentication is required and the result is a complete loss of availability.

Status

I reported this and was assigned CVE-2026-77622 for it, my own CVE, published as advisory GHSA-663m-7x7m-g4fw. Affects Sliver 1.7.3.
