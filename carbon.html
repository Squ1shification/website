Google OSS VRP — Carbon-lang Pre-Commit Artifact Poisoning

carbon-language/carbon-lang · CI/CD · artifact poisoning · GitHub Actions · Accepted

A malicious fork PR could make a trusted bot post arbitrary review comments — and retarget them at any PR — by poisoning a pre-commit artifact consumed by a privileged workflow.

The pattern

A pull_request workflow (runs fork code, no secrets) produces an artifact; a workflow_run workflow (runs with secrets) consumes it without validation. Here the artifact is the git diff produced after the fork’s pre-commit hooks modify its own code — and the attacker controls both the source files and .pre-commit-config.yaml, so they fully control the diff’s contents.

The chain

pre_commit.yaml checks out the fork, runs its pre-commit hooks, and on failure uploads git diff plus a copy of the GitHub event file as an artifact. pre_commit_suggestions.yaml then fires on workflow_run — with no same-repository/fork check, no label gate, no environment protection — and pipes the downloaded diff into reviewdog using a bot PAT:

# pre_commit_suggestions.yaml  — runs on workflow_run, WITH secrets
- name: Create suggestions
  env:
    REVIEWDOG_GITHUB_API_TOKEN: ${{ secrets.CARBON_INFRA_BOT_FOR_REVIEWDOG }}
  run: |
    cat ./diff | \
      GITHUB_EVENT_PATH=./event \
      reviewdog -f=diff -f.diff.strip=1 -reporter=github-pr-review
Impact
  • Arbitrary review comments posted from the trusted carbon-infra-bot account on the PR.
  • Event-file tampering: a pre-commit hook can rewrite the GITHUB_EVENT_PATH file before it is copied into the artifact, changing the target PR number so reviewdog posts on any PR.
  • harden-runner in block mode stops exfiltration, but api.github.com stays reachable because reviewdog needs it — so the bot PAT remains usable against the GitHub API.
Status

Accepted by Google’s Open Source Software Vulnerability Rewards Program (OSS VRP).
